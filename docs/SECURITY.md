# ShadowTunnel — Модель безопасности

## Обзор

ShadowTunnel разработан с принципом "defense in depth". Каждый уровень имеет собственные механизмы защиты.

## Криптографическая модель

### Используемые примитивы

| Задача | Алгоритм | Размер ключа |
|--------|----------|-------------|
| Симметричное шифрование | AES-256-GCM | 256 бит |
| Обмен ключами | X25519 ECDH | 256 бит |
| Цифровые подписи | Ed25519 | 256 бит |
| Целостность | HMAC-SHA256 | 256 бит |
| Деривация ключей | HKDF-SHA256 | — |
| Генерация случайных чисел | os.urandom / SecureRandom | — |

### Perfect Forward Secrecy (PFS)

- Каждая сессия использует **эфемерные ключи X25519**
- Компрометация долгосрочного ключа (Ed25519) **не позволяет** расшифровать прошлые сессии
- Ротация ключей каждые 30 минут обеспечивает PFS внутри сессии

### Защита от атак

#### MITM (Man-in-the-Middle)
- Ed25519 подписи аутентифицируют обе стороны
- Challenge-response предотвращает подмену
- Клиент пинирует публичный ключ сервера

#### Replay Attack
- 64-битные timestamp (миллисекунды) с допуском ±30 секунд
- Скользящее окно sequence numbers (1024)
- Уникальные nonce для каждого пакета (96 бит)

#### DDoS
- Handshake требует вычислительно дорогих операций от клиента
- Cookie-based rate limiting
- Максимальное число сессий ограничено

#### Traffic Analysis
- Random padding скрывает реальные размеры пакетов
- TLS mimicry маскирует протокол под HTTPS
- Keepalive создаёт фоновый шум

## Безопасность генерации случайных чисел

- **Python**: `os.urandom()` — криптографически стойкий PRNG
- **Android**: `java.security.SecureRandom` — аппаратная энтропия
- **Ни при каких условиях** не используется `random.random()` или подобные

## Безопасность админ-панели

### Аутентификация
- Пароли хешируются **bcrypt** (12 rounds)
- JWT-токены с HMAC-SHA256 подписью
- Токены имеют TTL (1 час)

### Защита от веб-уязвимостей

| Уязвимость | Защита |
|------------|--------|
| XSS | Content-Security-Policy, экранирование Jinja2 |
| CSRF | CSRF-токены привязаны к сессии |
| Clickjacking | X-Frame-Options: DENY |
| MIME sniffing | X-Content-Type-Options: nosniff |
| SQLi | Нет SQL — файловое/in-memory хранилище |

### Ограничение доступа
- По умолчанию только localhost (127.0.0.1)
- Production: через SSH-туннель или Nginx reverse proxy
- Rate limiting через Nginx

## Безопасность ключей

### Хранение
- Приватные ключи: файлы с правами 600 (только owner)
- На сервере: `/etc/shadowtunnel/server.key`
- На клиенте: AppData/ShadowTunnel/ (Windows), app sandbox (Android)

### Ротация
- Сессионные ключи: каждые 30 минут автоматически
- Долгосрочные ключи: ручная ротация (рекомендуется раз в год)

## Потенциальные риски и митигация

### Риск: Компрометация VPS
**Митигация**: PFS означает, что прошлые сессии не расшифруются. Ротация серверного ключа, уведомление клиентов.

### Риск: Утечка конфигурации клиента
**Митигация**: Конфигурация содержит только публичный ключ сервера. Приватный ключ клиента хранится отдельно.

### Риск: DPI-блокировка
**Митигация**: TLS mimicry, random padding. При обнаружении — смена порта, добавление нового метода обфускации.

### Риск: Buffer overflow
**Митигация**: Python — язык с управляемой памятью. Все размеры валидируются перед обработкой. Нет использования ctypes для критических операций.

## Рекомендации по усилению безопасности

1. **Запуск в Docker** с ограниченными capabilities
2. **Firewall**: разрешить только UDP 51820 и SSH
3. **Обновления**: регулярно обновлять зависимости (`pip install --upgrade`)
4. **Мониторинг**: настроить алерты на аномальный трафик
5. **Логирование**: хранить логи на отдельном сервере
6. **Смена дефолтного пароля** admin panel при установке
7. **Let's Encrypt** вместо self-signed сертификатов для production
